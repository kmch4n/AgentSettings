# debug-assist スキル

エラーメッセージ・スタックトレース・症状から原因を特定し、解決手順を提示する。

## ステップ1: エラー情報の収集

`$ARGUMENTS` にエラーメッセージやスタックトレースが含まれている場合はそれを使う。
含まれていない場合は、ユーザーに以下を確認する:
- エラーメッセージ全文
- 発生したコマンドや操作
- 直前に行った変更

## ステップ2: エラーの分類

エラーの種類を特定する:
- **SyntaxError / TypeError / ImportError** → コード・依存関係の問題
- **ConnectionError / TimeoutError** → ネットワーク・外部サービスの問題
- **PermissionError / FileNotFoundError** → ファイルシステムの問題
- **AssertionError / TestFailure** → テストの失敗
- **ビルドエラー** → 設定・依存関係の問題

## ステップ3: 関連コードの調査

スタックトレースに含まれるファイルパス・行番号を Read で読み込み、該当箇所とその前後のコードを確認する。

エラーメッセージのキーワードで Grep を使ってコードベースを検索する。

## ステップ4: 原因の分析と解決策の提示

以下の形式で出力する:

```
## エラーの概要
<エラーの種類と1行の説明>

## 原因の候補
1. **[可能性: 高/中/低]** <原因の説明>
   - 確認方法: <具体的な確認手順>
   - 該当箇所: <ファイルパス:行番号>

## 推奨する解決手順
1. <手順1>
2. <手順2>

## 再発防止策
<根本原因が判明した場合の予防策>
```

## 注意事項
- 原因が確定していない場合は「可能性」として提示し、断定しない
- 複数の原因候補がある場合は確認しやすい順に並べる
- コードの修正は提案するが、ユーザーの確認なしに自動適用しない
