# ask-why スキル

設計判断・実装選択の背景を git log・コメント・ドキュメントから調査して説明する。

## 引数の処理

`$ARGUMENTS` に調査対象を指定する（ファイルパス・関数名・ライブラリ名・ディレクトリ名など）。
引数がない場合はユーザーに「何について調べますか？」と確認する。

## ステップ1: 対象の特定

`$ARGUMENTS` から調査対象を読み取り、該当ファイル・コードを Read で確認する。

## ステップ2: git log の調査

```bash
# 対象ファイルの変更履歴
git log --follow --pretty=format:"%h %ad %s%n%b" --date=short -- <対象ファイル>

# 対象ファイルに関連するコミットの詳細
git log --follow -p --date=short -- <対象ファイル> | head -200
```

コミットメッセージに意図・背景・理由が書かれていないか確認する。

## ステップ3: コードコメントの調査

対象ファイル・関連ファイルのコメント・docstring・TODO・NOTE を Grep で検索する。

## ステップ4: ドキュメントの調査

- README.md / docs/ に関連する記述がないか確認する
- ADR（Architecture Decision Records）ファイルがあれば読む（`docs/adr/` 等）
- CHANGELOG.md に関連するエントリがないか確認する

## ステップ5: 推論と説明

収集した情報をもとに、以下の形式で出力する:

```
## 「<対象>」の設計意図・背景

### わかったこと
<git log・コメント・ドキュメントから読み取れた意図>

### 推測される理由
<直接的な記録がない場合、コードの構造から推測される背景>

### 関連する変更履歴
| コミット | 日付 | 内容 |
|---------|------|------|
| <hash> | <date> | <message> |

### 不明な点
<調査しても理由が特定できなかった部分>
```

## 注意事項
- 推測と確認できた事実を明確に区別して提示する
- 証拠がない場合は「記録が見つかりませんでした」と正直に伝える
- コードの変更は一切行わない
